# OS Term Project Starter
เอกสารนี้รวบรวมวิธีเตรียมโปรเจ็กต์ คอมไพล์และรันโปรแกรม รูปแบบข้อมูลที่ต้องใช้ และข้อควรรู้ก่อนทดลองใช้งาน

โปรเจ็กต์วิชา 517321-Operating Systems นี้จำลองการส่งงานเข้าระบบตามเวลาที่กำหนด การจัดคิวงานด้วยวิธี FCFS หรือ Priority การทำงานพร้อมกันของ Worker Thread และการใช้ทรัพยากรร่วมกัน เช่น `PRINTER` และ `DATABASE`

## 1. วิธีคอมไพล์และรันโปรแกรม

### สิ่งที่ต้องเตรียม

- ติดตั้ง **JDK 8 ขึ้นไป** และตรวจสอบว่าเรียกใช้คำสั่ง `java` กับ `javac` จาก Terminal ได้
- เปิด Terminal แล้วเข้าไปที่โฟลเดอร์หลักของโปรเจ็กต์ ซึ่งเป็นโฟลเดอร์ที่มี `src` และ `workloads`
- ไฟล์ workload ต้องอ่านด้วย encoding แบบ UTF-8

### คอมไพล์โปรแกรม

เรียกใช้คำสั่งต่อไปนี้จากโฟลเดอร์หลักของโปรเจ็กต์ เพื่อเก็บไฟล์ที่คอมไพล์แล้วแยกจาก Source Code:

```powershell
New-Item -ItemType Directory -Force out | Out-Null
javac -encoding UTF-8 -d out src\*.java
```

เมื่อคอมไพล์สำเร็จ ไฟล์ `.class` จะถูกสร้างไว้ในโฟลเดอร์ `out` หากมีการแก้ไขโค้ด ให้รันคำสั่งคอมไพล์ใหม่ก่อนรันโปรแกรม

### รันโปรแกรม

ใช้ Terminal ที่อยู่ในโฟลเดอร์หลักเดิม แล้วรันคำสั่งตัวอย่างนี้:

```powershell
java -cp out Main workloads\jobs_standard.csv priority 3 1 2
```

ระหว่างที่โปรแกรมทำงาน โปรแกรมจะแสดง log ความคืบหน้าใน Terminal เมื่อทุกงานเสร็จ โปรแกรมจะแสดงตาราง `SUMMARY REPORT` ใน Terminal เช่นกัน หากต้องการบันทึกผลลัพธ์ ให้บันทึก output เป็น UTF-8 ในโฟลเดอร์ `Logs` ไฟล์ workload ตัวอย่างมีดังนี้:

| ไฟล์ | ใช้สำหรับทดสอบ |
|---|---|
| `jobs_standard.csv` | ทดลองเปรียบเทียบวิธีจัดคิวและจำนวน Worker |
| `jobs_printer.csv` | ทดลองกรณีที่หลายงานต้องใช้ `PRINTER` |
| `jobs_db.csv` | ทดลองการใช้ `DATABASE` |
| `jobs_same_priority.csv` | ทดลองการจัดลำดับเมื่องานมี priority เท่ากัน |
| `jobs_single.csv` | ทดลองกรณีมีงานเดียวและการหยุดระบบ |

ตัวอย่างคำสั่งสำหรับเปลี่ยน workload หรือวิธีจัดคิว:

```powershell
java -cp out Main workloads\jobs_standard.csv fcfs 3 1 2
java -cp out Main workloads\jobs_standard.csv priority 3 1 2
java -cp out Main workloads\jobs_printer.csv priority 3 2 2
```

หากต้องการเก็บผลลัพธ์ไว้ดูภายหลัง สามารถ redirect output จาก Terminal ไปยังไฟล์ได้ เช่น:

```powershell
java -cp out Main workloads\jobs_standard.csv priority 3 1 2 | Set-Content -Encoding UTF8 Logs\my_run.log
```

พาธของไฟล์ workload และไฟล์ log ในตัวอย่างอ้างอิงจากโฟลเดอร์ที่ Terminal เปิดใช้งานอยู่ในขณะนั้น

## 2. ค่าที่ต้องระบุตอนรันโปรแกรม

โปรแกรมต้องได้รับ argument ทั้งหมด **5 ค่า** และต้องเรียงตามลำดับนี้:

```text
java -cp out Main <workload.csv> <fcfs|priority> <workers> <printerPermits> <databasePermits>
```

| ลำดับ | ค่า | ความหมายและเงื่อนไข | ตัวอย่าง |
|---|---|---|---|
| 1 | `workload.csv` | พาธของไฟล์ CSV ที่มีข้อมูลงานอย่างน้อย 1 งาน | `workloads\jobs_standard.csv` |
| 2 | `fcfs` หรือ `priority` | วิธีจัดคิวงาน โดยไม่แยกตัวพิมพ์เล็กกับตัวพิมพ์ใหญ่ | `priority` |
| 3 | `workers` | จำนวน Worker Thread ต้องเป็นจำนวนเต็มตั้งแต่ 1 ขึ้นไป | `3` |
| 4 | `printerPermits` | จำนวนงานสูงสุดที่ใช้ `PRINTER` พร้อมกันได้ ต้องเป็นจำนวนเต็มตั้งแต่ 1 ขึ้นไป | `1` |
| 5 | `databasePermits` | จำนวนงานสูงสุดที่ใช้ `DATABASE` พร้อมกันได้ ต้องเป็นจำนวนเต็มตั้งแต่ 1 ขึ้นไป | `2` |

สำหรับ `priority` ตัวเลขยิ่งน้อยหมายถึงงานยิ่งสำคัญ โดย `1` เป็นระดับที่สำคัญที่สุด หากงานมี priority เท่ากัน โปรแกรมจะเรียงตามลำดับแถวที่ปรากฏในไฟล์ CSV ส่วน `fcfs` จะจัดการงานตามลำดับที่งานเข้าคิว

## 3. รูปแบบไฟล์ Workload CSV

แต่ละแถวในไฟล์ CSV ต้องมีทั้งหมด 6 คอลัมน์ และเรียงตามลำดับต่อไปนี้:

```csv
id,arrivalMs,priority,workMs,resource,resourceMs
J01,0,5,2500,NONE,0
J02,100,1,300,PRINTER,1200
```

| คอลัมน์ | ความหมายและเงื่อนไข |
|---|---|
| `id` | รหัสของงาน ต้องไม่เว้นว่างและห้ามซ้ำกันภายในไฟล์เดียวกัน |
| `arrivalMs` | เวลาที่กำหนดให้งานเข้าระบบ หน่วยเป็นมิลลิวินาที ต้องเป็นจำนวนเต็มตั้งแต่ 0 ขึ้นไป |
| `priority` | ระดับความสำคัญของงาน ต้องเป็นจำนวนเต็มตั้งแต่ 1 ขึ้นไป โดย `1` หมายถึงงานที่สำคัญที่สุด |
| `workMs` | ระยะเวลาจำลองการทำงานหลัก หน่วยเป็นมิลลิวินาที ต้องเป็นจำนวนเต็มตั้งแต่ 0 ขึ้นไป |
| `resource` | ชนิดทรัพยากรที่งานต้องใช้ ระบุได้เฉพาะ `NONE`, `PRINTER` หรือ `DATABASE` และใช้ตัวพิมพ์เล็กหรือใหญ่ก็ได้ |
| `resourceMs` | ระยะเวลาที่ใช้ทรัพยากร หน่วยเป็นมิลลิวินาที หาก `resource` เป็น `NONE` ต้องกำหนดเป็น `0` แต่หากมีการใช้ทรัพยากร ต้องกำหนดค่ามากกว่า `0` |

โปรแกรมอ่านไฟล์ที่มีหรือไม่มีหัวตารางก็ได้ และรองรับบรรทัดว่าง, UTF-8 BOM รวมถึงรูปแบบขึ้นบรรทัดใหม่ทั้ง LF และ CRLF นอกจากนี้ โปรแกรมจะตัดช่องว่างด้านหน้าและด้านหลังของแต่ละค่าให้อัตโนมัติ อย่างไรก็ตาม แต่ละแถวต้องมี 6 คอลัมน์พอดี และไม่รองรับการใช้เครื่องหมาย quoting หรือ escape เพื่อใส่ comma ภายในค่า

## 4. ข้อจำกัดและสิ่งที่ควรรู้

- วิธีจัดคิวแบบ Priority ใช้เรียงลำดับเฉพาะงานที่ยังรออยู่ใน Ready Queue เท่านั้น **ไม่ใช่ preemptive scheduling** หมายความว่า เมื่องานเริ่มทำงานบน Worker แล้ว โปรแกรมจะไม่หยุดงานนั้นเพื่อแทรกงานที่มี priority สูงกว่า
- งานหนึ่งรายการใช้ทรัพยากรได้ไม่เกิน 1 ชนิด ได้แก่ `NONE`, `PRINTER` หรือ `DATABASE` และจะขอใช้ทรัพยากรหลังจากทำงานหลักเสร็จแล้ว
- จำนวน Worker และค่า permit ต้องไม่น้อยกว่า 1 โดย permit ใช้จำกัดจำนวนงานที่เข้าถึงทรัพยากรเดียวกันได้พร้อมกัน และใช้ Semaphore แบบ fair
- พาธไฟล์จะอ้างอิงจากโฟลเดอร์ที่เปิด Terminal อยู่ ไม่ใช่ตำแหน่งของไฟล์ `.java` ดังนั้น หากเปิด Terminal จากโฟลเดอร์อื่น ต้องแก้พาธในคำสั่งให้ถูกต้อง
- เวลาที่งานเข้าระบบจริงอาจไม่ตรงกับ `arrivalMs` ทุกครั้ง และค่าเวลาใน log หรือ summary อาจเปลี่ยนไปในแต่ละรอบ เพราะระบบปฏิบัติการเป็นผู้จัดสรรเวลาให้แต่ละ Thread รวมถึงเวลาที่ต้องรอใช้ทรัพยากร
- ลำดับงานใน Summary ยึดตามลำดับแถวในไฟล์ CSV จึงอาจไม่ตรงกับลำดับที่งานเริ่มหรือทำเสร็จ
- Summary แสดงค่า Waiting Time (`start - actual arrival`), Turnaround Time (`completion - actual arrival`), Throughput (`จำนวนงาน × 1,000 ÷ completionMs สูงสุด`) และ Resource Wait Time โดยค่าเฉลี่ย Resource Wait จะคำนวณเฉพาะงานที่มีการใช้ทรัพยากร
- หากระบุ argument ไม่ครบหรือไม่ถูกต้อง เปิดไฟล์ workload ไม่ได้ หรือไฟล์มีรูปแบบไม่ถูกต้อง โปรแกรมจะแสดง error และหยุดทำงาน โดยไม่แสดง Summary ที่มีข้อมูลไม่ครบ
- Job มีสถานะของระบบแยกจาก `Thread.State`: `ARRIVED`, `READY`, `RUNNING`, `WAITING_RESOURCE` และ `COMPLETED`
- ไฟล์ `.class` เป็นไฟล์ที่ได้จากการคอมไพล์และจะอยู่ใน `out` ไม่ใช่ไฟล์ซอร์สสำหรับแก้ไข หากต้องการเปลี่ยนโค้ด ให้แก้ไฟล์ `.java` แล้วคอมไพล์ใหม่ โฟลเดอร์ `out` ไม่จำเป็นต้องรวมในงานส่ง

## 6. ชุดทดสอบเพิ่มเติม

```powershell
java -cp out Main workloads\jobs_single.csv priority 1 1 1
java -cp out Main workloads\jobs_db.csv priority 3 1 2
java -cp out Main workloads\jobs_same_priority.csv priority 2 1 1
```

ควรตรวจว่า `jobs_single.csv` จบได้เอง, `jobs_db.csv` ใช้ DATABASE ได้พร้อมกันไม่เกิน 2 งาน และ `jobs_same_priority.csv` เรียงตามลำดับแถวเมื่อ priority เท่ากัน
